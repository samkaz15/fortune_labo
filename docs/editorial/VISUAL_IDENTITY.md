# Fortune Labo Visual Identity

Version: `visual-style-0.1.0`。状態: Editorial Foundationの画像試作基準。顧客向け公開、商品提供、実在人物・施設の写真利用を承認するものではない。

落ち着いた日本語の編集記事に合う、明瞭で静かなビジュアルを使う。読者の考えを整理するために画像を置き、占いや成果の確実性を演出しない。自然光、余白、控えめな線や水彩の質感、紙・机・暮らしの道具など、記事内容に具体的な関係がある題材を選ぶ。

## 共通表現

白・生成り・薄いグレーを基調に、必要な箇所だけセージや抑えた青緑を用いる。明暗や質感で主役を区別し、装飾で注意を奪わない。写真風の画像でも生成物は生成物として記録し、実際の訪問・本人・顧客事例の証拠にしない。

featured imageは原則1枚。タイトルを画像内に重複させず、記事の主題と読む場面が伝わる構図にする。各H2は、理解を助ける場面・図解・比較・手順が本当に必要か検討し、本文や既存表で十分なら理由つきのNO_IMAGEを選ぶ。画像枚数を品質基準にしない。

図解は概念の関係が正しいことを優先する。日本語の長文、表の全文、本文コピーをAI生成のraster画像に埋め込まない。必要な説明はHTML/SVGのnative text層や本文に置く。短いラベルをrasterへ使う場合も、誤字・読みやすさの実画像確認が必要である。SVGが制作できてもWordPressがそのまま受け付けると判断せず、A25で変換またはnative HTML化の可否を別途確認する。

## 避ける表現

星空・宇宙・過剰な光輪や発光、金と紫の定型装飾、水晶球、神秘性だけを強調するクリシェを避ける。根拠のない効能、未来の保証、不安や焦りを増幅する構図、実在しない専門家・顧客・現地体験の演出を使わない。実在人物や場所の権威を借りる見せ方は、出典と利用権が確認できる素材に限る。

## 実画像の確認

altは内容の理解に必要な対象と関係を簡潔に説明し、キーワードの羅列にしない。captionは必要な場合だけ補足する。生成写真風の素材は実写の現地記録と誤認させず、必要に応じ「イメージ」「生成イラスト」等と明示する。

実際のファイル、hash、寸法、mime、生成元または利用権を記録する。promptを保存しただけで画像生成を完了にしない。失敗・未生成・NO_IMAGEを区別し、実画の文字崩れ、不自然な物体、色の一貫性、本文との整合をA11/QAで確認する。A11の機械検査はこれらの視覚的な正しさを保証しない。

## 変更管理

記事のDraft/Blueprint hash、article_version、visual_style_versionをplanへ固定する。記事や見出しが変わったらplanを再確認し、画像だけを以前の内容へ結び付けたまま利用しない。Visual Identity変更時は版とplanの差分を確認する。A07/A08の保存済みBrief・Draft・runを、画像追加のために書き換えない。
