# ゲートと撤退基準

WBS には5つのゲートがあります。各ゲートは**その時点で10億円到達が
まだ数学的に可能かどうか**を判定します。

目的は目標を守ることではなく、**到達不能が確定した時点で早く気づくこと**です。

---

## ゲート一覧

| ゲート | 時期 | 月数 | 通過条件 | WBS |
| --- | --- | --: | --- | --- |
| **G1** | 2026-11-30 | M3 | 月商150万円 / 事業モデル決定 / 法務基盤完成 | 0.G |
| **G2** | 2027-02-28 | M6 | MVPリリース済 / 課金者300人 | 1.G |
| **G3** | 2027-08-31 | M12 | 3ヶ月継続率40% / 課金会員5,000人 / 月商1,000万円 | 2.G |
| **G4** | 2028-02-29 | M18 | 課金会員20,000人 / 月商4,000万円 / LTV/CAC≧3 | 3.G |
| **G5** | 2028-08-31 | M24 | 月商8,333万円（年商10億円ランレート） | 4.G |

---

## 各ゲートの意味

### G1（M3）— 構造が決まったか

10億円が対面鑑定の延長にないことは既に分かっています（`revenue-model.md` §2）。
G1で問うのは「**では何をやるか**」が決まったかどうかです。

| 判定 | 対応 |
| --- | --- |
| 通過 | P1（MVP構築）へ |
| 月商150万円のみ未達 | 継続。ただしP1の初期ユーザー獲得の見通しを下方修正 |
| 事業モデル未決定 | **P1に進まない。** 決まっていない状態でMVPを作るのが最も損失が大きい |

### G2（M6）— 人はお金を払うか

課金者300人は小さな数字に見えますが、**「払う人が存在する」ことの最初の証拠**です。
ゼロなら、以降の全ての予測の土台がありません。

| 判定 | 対応 |
| --- | --- |
| 300人以上 | P2へ |
| 100〜299人 | 課金導線・価格を見直してP2へ。ただしG3の基準は据え置き |
| 100人未満 | **プロダクト方針の転換。** 機能ではなく価値提案から作り直す |

### G3（M12）— PMFがあるか（最重要ゲート）

**10億円の成否は実質ここで決まります。** 24ヶ月目の月商8,333万円に対し、
12ヶ月目に1,000万円（1/8）が必要です。これは指数成長を前提にした
最低ラインで、余裕のある数字ではありません。

継続率40%は `positioning.md` との矛盾に対する回答でもあります。
一次情報を持つアプリが、汎用AI占いアプリを継続率で上回れなければ、
moat移設仮説（`revenue-model.md` §6）は棄却されます。

| 判定 | 対応 |
| --- | --- |
| 全項目通過 | P3へ。有料広告を開始してよい |
| 継続率のみ未達 | **スケール投資をしない。** 穴の空いたバケツに水を注ぐのが最悪の選択 |
| 課金会員・月商が半分以下 | **2年10億は不可能と確定。** 目標を再設定する（下記参照） |

### G4（M18）— 資本を入れて伸びるか

有料広告と採用に資本を投下した結果が出る時点。
LTV/CAC≧3 が成立していなければ、広告を止めて
オーガニック中心に戻す判断が要ります。

| 判定 | 対応 |
| --- | --- |
| 全項目通過 | P4へ |
| LTV/CAC < 3 | 広告停止。ARPU引き上げ（`revenue-model.md` §4）に切り替え |
| 月商2,000万円未満 | 24ヶ月での到達は不可能。**30〜36ヶ月へ計画を延長** |

### G5（M24）— 到達したか

| 判定 | 対応 |
| --- | --- |
| 月商8,333万円以上 | 目標達成。次の2年計画へ |
| 未達 | **未達幅と要因を記録し、翌年計画へ引き継ぐ。** 失敗として処理しない |

## 目標の再設定について

G3またはG4で未達が確定した場合、取りうる選択肢は3つです。
**どれも失敗ではありません。**

| 選択肢 | 内容 | 向いている状況 |
| --- | --- | --- |
| **期間を伸ばす** | 10億円の到達を36〜48ヶ月に | 単位あたりの経済性は成立、伸び方が遅いだけ |
| **金額を下げる** | 2年で1〜3億円に | 構造は良いが市場規模が想定より小さい |
| **構造を変える** | プラットフォームをやめ、高単価の対面・法人特化へ | 継続率が立たず、moat移設仮説が棄却された場合 |

3番目は `positioning.md` が元々推奨していた方向です。
そこに戻ることは後退ではなく、**証拠に従って仮説を更新した結果**です
（`/AGENTS.md` の決定階層）。

---

## ゲート判定の運用

- 判定は**人間のみ**が行います（自動化レベル C）。AIは数値を用意するだけです
- 判定結果は通過・未達にかかわらず**必ず記録**します
- 未達を「もう少しで届く」として通過させないこと。それがゲートを置く意味を失わせます
- 判定日はWBS上の固定日です。前倒し・先送りしません
