## 編集方法

`wbs-master.md` と `wbs-master.csv` を直接編集しないでください。両者が食い違います。

```sh
# 1. build.py の ROWS を編集
# 2. 再生成
python3 fortune_labo/wbs/build.py

# 3. 差分が出ていないか確認（CI用）
python3 fortune_labo/wbs/build.py --check
```

`build.py` は生成前に必ず検証を走らせます。以下は生成そのものが失敗します。

- 存在しないWBS番号への依存
- 開始日が期限より後の行
- **FS依存なのに先行タスクの完了前に開始している行**
  （並行開始が正しいなら `依存` に `(SS)` を明記する。現在20件）

## 列の定義

参照シートの列構成を踏襲しています。

| 列 | 内容 |
| --- | --- |
| WBS番号 | 階層番号。`0` / `0.1` / `0.1.1` の3階層。`*.G` はゲート |
| フェーズ | P0〜P5 と継続運用 |
| タスク | 作業名 |
| 定義 | 何をもって完了とするか、なぜ必要か |
| 依存 | 先行するWBS番号。`-` は依存なし。既定は **FS**（先行完了→後続開始）、`0.5.1(SS)` は並行開始可 |
| アウトプット | 成果物。これが出ていなければ未完了 |
| 担当 | 人間 / Codex / エージェントID（A06, A10-X 等） |
| 自動化レベル | A〜D。下表参照 |
| 開始日・期限・日数 | 暦日ベース |
| 進捗 | 常に0%で生成。実績はスプレッドシート側で更新する |

### 自動化レベル（参照シートの定義を継承）

| レベル | 意味 | 例 |
| --- | --- | --- |
| **A** | 全自動。AIが実行し、人間は結果を確認するのみ | KPIレポート生成、禁止表現の検出 |
| **B** | AI下書き → 人間承認 | 記事制作、SNS投稿文、競合分析 |
| **C** | 人間のみ。AIでは代替不可 | 神社訪問、占術判断、対面鑑定、全公開物の最終承認、**ゲート判定** |
| **D** | Codex実装（コード変更） | API接続、アプリ開発、スキーマ実装 |

レベルCは「まだ自動化していない」ではなく「**自動化しないと決めた**」ものです。
参照シートの「自動化しないと決めたもの」の方針を引き継いでいます。

- SNSへの自動投稿 — 承認なしの発信は炎上とコンプラのリスク
- 顧客への自動メッセージ送信 — 個別性が価値の事業で自動化すると価値が消える
- 本番WordPressへの自動反映 — `/AGENTS.md` の公開ルール
- 神社の体感・訪問記録の生成 — ここを自動化したら moat が消える
- 占術判断そのもの — 「誰が言ったか」が価値

## スプレッドシートとの同期

```
build.py（真正）→ wbs-master.csv → Googleスプレッドシートに貼り付け
                                          ↓
                                   進捗%・実績日はシート側で更新
                                          ↓
                            計画変更が必要になったら build.py に戻す
```

**計画（タスク・依存・期限）はリポジトリが真正、実績（進捗・実日付）はシートが真正**、
という分担です。両方を両方で管理しようとすると必ず食い違います。

### 貼り付け手順

1. `wbs-master.csv` を開く
2. 全選択してコピー
3. スプレッドシートの新規タブに貼り付け → 「データ」→「テキストを列に分割」→ カンマ
4. ガントチャート部分は既存テンプレートの数式をそのまま使う
