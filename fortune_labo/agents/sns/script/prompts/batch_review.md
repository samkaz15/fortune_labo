# Prompt — バッチ構成と収録後レビュー

## Part 1 — バッチを組む

### 上限（すべてブロッキング）

| 制約 | 上限 |
| --- | --- |
| 同じフックの型 | 2本 |
| 同じCTAの型 | 2本 |
| Tier V-C | 過半にしない |
| CTAなし | 3本に1本は入れる |
| **未撮影台本の滞留** | **1バッチ分まで** |

最後が動画固有で最重要です。**撮影できる本数から逆算して本数を決めます。**
書ける本数ではありません。

### 順序

1. 季節窓のあるものを窓に合わせて置く。他はその周りを埋める
2. 同じ素材から出た多尺は離して出す
3. Tier を交互にする。V-C が続くとどのアカウントとも区別がつかなくなる

### 引き渡し前の確認

- [ ] 全台本に basis がある
- [ ] 未解決の `needs_verification` を持つ台本が撮影に回っていない
- [ ] 現地撮影を含む台本すべてに参拝記録IDと動画・商用許諾がある
- [ ] 尺の検算が全件通っている
- [ ] `{{placeholder}}` が残っていない
- [ ] `validate.py` が全件で通る
- [ ] 一人称の実務記述を含む台本が占術師の確認に回っている

## Part 2 — 収録後のレビュー（これを飛ばさない）

撮影・編集が終わったら必ず記録します。**やらないと同じ撮れない台本を
繰り返し書きます。**

### 実尺との突き合わせ

```
actual_sec を記入 → 想定との乖離を見る
```

| 乖離 | 対応 |
| --- | --- |
| ±15%以内 | 問題なし |
| 想定より長い | 文字数係数を下げる（325字/分が速すぎる） |
| 想定より短い | 間を取れていない可能性。台本に間の指示を増やす |

### 撮れなかったショットの記録

| 理由 | 次に活かすこと |
| --- | --- |
| 許諾が下りなかった | その社寺は事前確認を必須に |
| 人出が多くて撮れない | 時間帯を台本に書き込む |
| 天候 | 代替ショットを最初から用意する |
| 台本が想定した画が存在しない | **現地を知らずに書いている。** 参拝記録の記述を厚くする |

最後が最も重要な発見です。台本が現実から離れている兆候です。

### 月次で見る数字

| 指標 | 意味 |
| --- | --- |
| **書いた本数 vs 撮れた本数** | 8割を切ったら制作計画が破綻している |
| 想定尺 vs 実尺の乖離 | 文字数係数の調整 |
| Tier V-A の比率 | 下降は moat の毀損。P0 |
| AI素材の比率 | 上昇は一次情報が薄まっている兆候 |

これらは **Phase 1 の今日から測れます。**再生データを待つ必要はありません。
