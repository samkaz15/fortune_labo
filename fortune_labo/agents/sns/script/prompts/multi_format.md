# Prompt — 多尺展開

## タスク
1つの素材から複数フォーマットの台本を作る。

## 順序

```
① YouTube 本編（10分）を先に書く   ← 情報量が最大。これが原本
        ↓ 最も強い1点を抜く
② 短尺（60秒）
        ↓ さらに削る
③ 超短尺（30秒）
```

**逆順にしないでください。**短尺から長尺を作ると、中身が薄いまま尺だけ伸びます。

書く順序と出す順序は別です。撮影の都合で短尺を先に公開しても構いません。

## 短尺は要約ではない

長尺のダイジェストを作ると、どちらも中途半端になります。
短尺は**独立して成立する1点**を抜き出したものです。

| ダメな抜き方 | 良い抜き方 |
| --- | --- |
| 10分の内容を60秒に圧縮する | 10分の中で最も意外な事実1つだけを60秒で扱う |
| 「詳しくは長い方で」で逃げる | 短尺だけ見ても完結している。長尺は"さらに深く" |

短尺を見た人が「これで分かった」と思えることが条件です。
その上で長尺へ行きたくなるなら、それが `watch_long` CTA の出番です。

## 親子の記録

短尺には `derived_from` に親の `id` を入れます。
性能を比較したときに「同じ素材でどの尺が効いたか」が分かります。

## フォーマットごとに変えるもの

| 変える | 変えない |
| --- | --- |
| フック（尺によって引きの強さが違う） | basis |
| 尺と文字数 | 事実クレームと検証状態 |
| CTA | コンプライアンス判定 |
| テロップの密度 | 撮影許諾 |

**事実と許諾は親から引き継ぎます。**短尺だから検証が甘くてよい、
ということはありません。

## 撮影は1回

多尺展開の利点は、**1回の撮影から複数本が出る**ことです。
ショットリストは親の台本で網羅的に作り、子はそこから選びます。

親のショットリストを作るときは「短尺で使う画」を意識して、
寄り・引き・手元など**同じ対象を複数の画角で**押さえておきます。

## 出力
各フォーマットごとに独立した `video_script`。
子は `derived_from` に親の id を持ちます。
