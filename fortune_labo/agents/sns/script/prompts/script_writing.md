# Prompt — 台本執筆

## タスク
承認済みテーマ1件を `video_script` に変換する。

## Step 1 — 撮影できるかを最初に見る

| 確認 | 未確認なら |
| --- | --- |
| 現地撮影が要るか | — |
| 参拝記録があるか | **書かない。** blocked として欠落を記録する |
| 動画・商用の許諾があるか | **書かない。** 写真の許諾では足りない |
| 三脚可否 | 手持ち前提で構成する |
| 映り込みリスク | 引きを避けた構成にする |

ここを飛ばすと、以降の作業が全部無駄になります。

## Step 2 — 事実を分類する（執筆より前）

台本が主張する事実をすべて列挙し、`verified` / `needs_verification` /
`unverifiable` に分けます。**テロップに出すものは `in_caption: true`** を付けて
ください。画面に焼き付く情報は取り消しが効きません。

未検証があれば `video_fact_check_request` を出します。

## Step 3 — basis を確定する

- 空 → 書かない
- 運気が主題で `mechanism` だけ → 書かない
- `firsthand` を含む → `visit_record_id` が必須
- Tier V-A → `firsthand` か `practitioner_view` が必要

## Step 4 — 尺を決める

| 素材の量 | フォーマット |
| --- | --- |
| 章立てできる | YouTube 本編（原本として先に書く） |
| 強い1点がある | 短尺 |
| 意外な事実1つ | 超短尺 |

長尺から短尺を抜きます。逆はしません（`formats.md`）。

## Step 5 — フックを3案作る

視覚・音声・テロップの3層 × 3案。型を変えること。
選定基準は `writing.md` §2。**無音で成立するか**を必ず見ます。

## Step 6 — 本文を書く

話し言葉。ルビ。間。主観マーカー。史実のマーカー。
構成は `formats.md` の尺別テンプレート。

## Step 7 — ショットリスト

時系列に並べ、各ショットに `現地撮影` / `本人収録` / `図解` / `イメージ` を付けます。

- 時間が連続していること（飛びも重なりもなし）
- **何を撮るか**まで。構図・光・色は A11 の領域
- AI素材（図解・イメージ）が過半なら一次情報が薄い。組み直す

## Step 8 — 尺を検算する

```
音声の文字数 ÷ 325字/分 × 60 = 想定秒数
```

枠を超えたら**内容を削ります**。早口にしません。

## Step 9 — コンプライアンス自己点検

`rules.md` §2 を本文・フック・テロップ・タイトルすべてに当てます。
QAは二番目のゲートです。

| 書かない | 書く |
| --- | --- |
| 金運が上がります | 金運を意識するなら、昔から○○と言われてきました |
| やらないと運気が下がります | やってみると、生活が整うきっかけになります |
| 必ず／絶対／確実に | 削除。代替表現はありません |

## Step 10 — 検証して出す

```sh
python3 agents/sns/script/schemas/validate.py <file>
```

`status` を決めます。

- `draft` — すべて解決済み。QAへ
- `fact_check_pending` — 事実確認の返却待ち
- `blocked` — 参拝記録・許諾・事業ファクトが欠けている。
  `blocked_reason` に**何が無くて誰が供給できるか**を書く

blocked は正当な出力です。欠落を埋めずに進めることが問題です。
