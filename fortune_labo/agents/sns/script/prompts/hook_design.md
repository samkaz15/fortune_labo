# Prompt — 冒頭3秒の設計

## タスク
1本につきフック候補を3案以上作り、1つ選んで理由を記録する。

動画の成否はここで決まります。3秒で離脱されたら中身は届きません。

## 3層すべてを書く

```
視覚:    何が映っているか
音声:    何と言うか（無音スタートも選択肢）
テロップ: 何を出すか（音声の要約であって書き起こしではない）
```

| 層 | 役割 | よくある失敗 |
| --- | --- | --- |
| 視覚 | 止める | 知らない人の顔アップから始める |
| 音声 | 引く | 自己紹介から始める |
| テロップ | 無音対応 | 音声と一字一句同じにする |

## 型

| 型 | 例 |
| --- | --- |
| `surprising_fact` | 「ここ、江戸時代は海の底でした」 |
| `premise_denial` | 「お賽銭、金額に意味はありません」 |
| `order_reversal` | 「運気が落ちてるとき、財布より先に変えるものがあります」 |
| `concrete_date` | 「9月9日。五節句の最後の日です」 |
| `silent_action` | （黙って手水で清める）→ テロップ「正しい順番、知ってますか」 |
| `question` | 「なぜ節句は奇数の日なのか、考えたことありますか」 |

`concrete_date` と `surprising_fact` はフック自体が情報を運びます。
`question` と `premise_denial` は好奇心だけなので、本編が薄いと大きく裏切ります。

`silent_action` は無音視聴と相性が最高ですが、**TikTok では冒頭無音の離脱率が
高い**ので、Reels / Shorts 向きです。

## 2つの絶対条件

**1. 本編で回収できること。**
3秒で立てた問いに、本編が答えているか。答えていないフックは使いません。
保存率が落ちるだけでなく、信頼のコストが永久に残ります。

**2. 恐怖で引かないこと。**
「知らないと損」「やらないと運気が下がる」は `rules.md` §2.2 で禁止です。
これは表現の好みではなく法的露出の問題です。フックも規制の対象です。

## その他の禁止

| 失敗 | 例 |
| --- | --- |
| 効果の断定 | 「これで金運が上がる」 |
| 根拠のない数字 | 「99%の人が知らない」 |
| 煽り | 「まだ○○してるんですか」 |
| 型の反復 | 1バッチに `premise_denial` が3本 |

## 手順

1. **異なる3つの型**で3案作る。同じ型の言い換えは1案です
2. 各案について、誰が止まるかを言語化する
3. 2つの絶対条件に当てる
4. **無音で成立するか**を確認する（`silent_viable`）
5. 本編が約束を果たせる案を選ぶ。同点なら情報を運ぶ型を選ぶ
6. 落とした案と理由を記録する

## 出力
`video_script` の `hook`（3層）・`hook_candidates`（3案以上）・
`hook_choice_rationale`。
