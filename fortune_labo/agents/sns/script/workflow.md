# Script Agent — Workflow

## 全体の流れ

```
A06 SEO ── 季節暦・参拝計画      占術師 ── 参拝記録・撮影素材・収録時間
A02/A29 ── 検証済みの史実              ── 撮影許諾（動画・商用）
        │                                    │
        └──────────────┬─────────────────────┘
                       ▼
            A07 Content Strategy（テーマ承認）
                       ▼
        ┌──────────────────────────┐
        │  SCRIPT AGENT (A10-SC)   │
        │  テーマ→尺→フック→台本→   │
        │  ショットリスト→事実分類   │
        └──────────┬───────────────┘
                   ├────────► A29 Fact-Check
                   ▼                  │
             ★撮影前チェック ◄─────────┘
                   │  許諾・素材・尺・事実
                   ▼
              A28 QA Agent
       （コンプラ→事実→一次情報→編集）
                   ▼
            人間承認（台本）
                   ▼
              撮影（人間）
                   ▼
         A11 Creative（編集・サムネ）
                   ▼
            人間承認（完成尺）
                   ▼
               投稿（人間）
                   ▼
            A18 Analytics
                   ▼
          SCRIPT AGENT（解釈）
                   ▼
    実尺との突き合わせ → 次バッチへ
```

**人間承認が2回あります。**台本の段階と、完成した動画の段階。
撮影してから内容の問題が見つかると、撮り直しのコストが丸ごと無駄になるため、
台本の段階で1回止めます。

## 1本の制作手順

```
1. 撮影可否の確認      その画は撮れるか。許諾はあるか
                       ← ここが通らなければ以降すべて無駄

2. 素材の棚卸し        firsthand / practitioner_view が今あるか
                       無ければ Tier V-B / V-C に限定される

3. テーマと尺の決定    長尺の原本か、短尺単発か

4. 事実クレームの抽出  書く前に洗い出して分類する
                       ← 書いてから直すと台本ごと捨てることになる

5. 事実確認の依頼      verified でないものを A29 へ

6. フック3案           視覚・音声・テロップの3層 × 3案

7. 台本執筆            話し言葉・ルビ・間

8. ショットリスト      時系列＋素材種別

9. 尺の検算            文字数 ÷ 325字/分。超過なら内容を削る

10. コンプラ自己点検    フック・テロップ・タイトルを含む

11. 撮影前チェック      responsibilities.md §G の9項目

12. QA → 人間承認 → 撮影
```

**4 を 7 より前に置くのは意図的です。**動画は撮影コストが高いので、
事実が崩れたときの損失がテキストの比ではありません。

## 季節からの逆算

動画はテキストより工程が多いぶん、リードタイムが長くなります。

```
公開日                    例: 重陽の節句 9/9
   ↑ 2日
編集・サムネ              9/7
   ↑ 3日
撮影                      9/4
   ↑ 3日
人間承認（台本）          9/1
   ↑ 3日
QA                        8/29
   ↑ 7〜10日
事実確認の返却            8/22    ← 最長の工程
   ↑ 2日
事実確認の依頼            8/20
   ↑ 3日
台本執筆                  8/17
   ↑
テーマ選定・許諾確認      8月上旬  ← 神社の許諾はここ
```

**許諾取得と事実確認が律速です。**撮影3日前に企画を始めても間に合いません。

| 窓 | 必要リードタイム |
| --- | --- |
| 二十四節気 | 3週間 |
| 五節句 | 4週間 |
| 七五三・大祓 | 5週間 |
| 初詣・年始 | 8週間 |
| 年間見通し | 8週間＋翌年レビュー義務 |

テキスト（`agents/sns/x/workflow.md`）より1〜2週間長く見てください。

## 稼働の単位

### バッチ（月次・8〜15本）

制作の単位。上記の手順を通します。
**撮影できる本数から逆算**して本数を決めます（`rules.md` §1.5）。

### 週次

- 6週先までの季節窓の確認
- 返却された事実確認の処理
- 撮影待ち台本の滞留チェック
- 公開済み動画の Tier 2 指標の確認
- 公開済みにコンプラ・事実の問題が見つかればP0で上げる

### 月次

- Tier 1 / 2 / 3 レポート
- **書いた本数 vs 撮れた本数**の突き合わせ
- 想定尺 vs 実尺の乖離から文字数係数を調整
- フック型・Tier・フォーマット別の性能
- `tier_a_ratio` の監査 ← moat チェック
- 仮説台帳の更新

### 四半期

- A09 / A01 とのレビュー
- フォーマット構成の見直し（短尺と長尺の比率）
- 撮れなかった台本の原因分析
- 規制・プラットフォーム規約の変化確認

## 暫定運用（現状）

A07・A09・A29 がまだ存在しません。それまでは：

| 本来 | 暫定 |
| --- | --- |
| A07 がテーマ承認 | Script Agent が提案し、**人間が承認** |
| A09 が配分を決める | `positioning.md` からの仮説として扱う |
| A29 が検証 | 依頼を出して**保留**。人間が解決するまで撮影に進まない |

これは Script Agent の越権であり、そう記録します。
**公開には及びません。**公開は常に人間承認です。

## エスカレーション

`rules.md` §7 参照。動画で最も多いのは3つ：

| 事象 | 対応 |
| --- | --- |
| 撮影許諾が取れない／範囲外 | その台本を止める。代替テーマへ差し替え |
| 未撮影台本が1バッチ分を超えた | 制作計画が破綻。本数を落とす |
| 公開済みに問題を発見 | **即日。非公開化＋訂正動画の起案** |
