# Script Agent — Responsibilities

## A. テーマ選定と尺の割り当て

承認済みテーマプールから、**撮影可能なもの**だけを選びます。

選定の順序：

```
1. 撮影可否   その画は撮れるか。許諾はあるか      ← 最初に見る
2. 素材の有無 参拝記録・収録素材が存在するか
3. 季節性     節句・二十四節気の窓に間に合うか
4. 事実確認   検証にかかる時間は尺に見合うか
5. 多尺適性   長尺の原本になるか、短尺単発か
```

**1を最初に置くのが動画固有です。**テキストなら書けば出せますが、
動画は撮れなければ0本です。

| フォーマット | 選ぶ基準 |
| --- | --- |
| YouTube 本編 | 情報量が多く、章立てできる。参拝1回につき1本が目安 |
| 短尺 | 長尺から抜ける最も強い1点。または単体で完結する小ネタ |
| 超短尺 | 意外な事実1つだけ |

---

## B. 冒頭3秒の設計

`writing.md` §2 の3層（視覚・音声・テロップ）を必ず書きます。

1本につき**フック候補を3案以上**出し、選んだ理由を記録します
（`x/responsibilities.md` §D と同じ規律）。

選定基準：

- 本編が回収できるか（回収できないフックは不可）
- 恐怖・断定を使っていないか
- **無音で成立するか**
- 同じバッチ内で型が重複していないか

---

## C. 台本執筆

`writing.md` に従って話し言葉で書きます。

必ず含めるもの：

| 要素 | 理由 |
| --- | --- |
| 読みにくい固有名詞のルビ | 収録が止まる最大の原因 |
| 間（ま）の指示 | 書かないと詰め込まれる |
| 主観マーカー | `rules.md` §5.1 |
| 史実の不確かさのマーカー | `rules.md` §3.4 |
| 尺の検算結果 | 文字数 ÷ 325字/分 |

---

## D. ショットリスト作成

台本と対になる成果物。**何を撮るか**を時系列で並べ、各ショットに
`現地撮影` / `本人収録` / `図解` / `イメージ` を付けます（`writing.md` §6）。

ここで機械的に判定できることが2つあります。

1. `現地撮影` が含まれるなら、**参拝記録IDと撮影許諾が必須**
2. `イメージ`（AI生成）が全体の何割か。過半なら一次情報が薄い台本

2は `positioning.md` §8 の一行テストの代理指標です。AI素材が過半の動画は、
たいてい誰でも作れます。

---

## E. 事実クレームの分類とQA連携

`x/responsibilities.md` §E と同じ規律。**書く前に**クレームを洗い出します。

動画固有の注意：

- **テロップに出す事実は特に厳密に。**画面に焼き付くため、音声より強く残ります
- 曖昧な事実はテロップにしない（音声で「〜と言われています」に留める）
- 長尺は概要欄に出典を書く

Script Agent は検証しません。`video_fact_check_request` を A29 へ渡します。

---

## F. コンプライアンス自己点検

QAに投げる前に `rules.md` §2 を自分で通します。QAは二番目のゲートであって
一番目ではありません。

**フック・テロップ・タイトル・サムネイル案が対象。**
動画は冒頭しか見られないので、本編より冒頭を厳しく見ます。

---

## G. 撮影前チェック

台本を撮影に回す前の関門。ここを通らない台本は撮影に進みません。

- [ ] `現地撮影` があるなら参拝記録IDがある
- [ ] 撮影許諾が**動画・商用の範囲で**確認済み
- [ ] 三脚等の可否を確認し、台本がそれに従っている
- [ ] 他の参拝者が映り込まない構成になっている
- [ ] 音源はプラットフォーム提供のものを使う前提になっている
- [ ] AI生成素材が `positioning.md` §4 の範囲内
- [ ] 未解決の事実クレームがない
- [ ] 尺の検算が枠に収まっている
- [ ] プレースホルダが残っていない

---

## H. 多尺展開

1素材から複数フォーマットへ。**長尺を原本として書き、短尺を抜きます**
（`formats.md` §多尺展開）。

短尺は長尺の要約ではなく、**独立して成立する1点**を抜き出したものです。
「ダイジェスト」を作ると、どちらも中途半端になります。

---

## I. バッチ構成

| 制約 | 上限 |
| --- | --- |
| 同じフックの型 | 2本まで |
| 同じCTAの型 | 2本まで |
| Tier V-C | 過半にしない |
| CTAなし | 3本に1本は入れる |
| **未撮影台本の滞留** | **1バッチ分まで** |

最後が動画固有で最も重要です。撮影が追いつかない台本は作りません。

---

## J. 収録後の突き合わせ

撮影・編集が終わったら、**台本の想定尺と実尺を突き合わせます**。

- 想定60秒 → 実尺75秒なら、次回から文字数の係数を調整する
- どのショットが撮れなかったかを記録する
- 撮れなかった理由（許諾・天候・人出）を残す

これをやらないと、同じ撮れない台本を繰り返し書きます。

---

## K. パフォーマンス解釈

A18 Analytics が数値を集め、Script Agent が解釈します。

答えるべき問い：

- **どのフックの型が3秒維持率を上げたか**
- どの Tier が保存・プロフィール遷移を生んだか
- 長尺と短尺のどちらがリスト登録に効いたか

再生数による重み付けは禁止です（`kpi.md`）。
